# Autonomous Research Framework — Design & Implementation Log

> Version: 1.0
> Created: 2026-03-24
> Purpose: 이 문서는 Claude Code를 활용한 자율 연구 수행 프레임워크의 설계, 구현, 운영 경험을 기록한다.
> 이 프레임워크 자체가 연구 자산이며, 반복 개선을 통해 발전시킨다.

---

## 1. 동기와 배경

### 1.1 문제 정의
- 연구자가 다수 프로젝트를 동시 진행할 때, 개별 프로젝트에 매일 깊이 관여하기 어려움
- 특히 CFD 시뮬레이션 + 데이터셋 생성 + 라벨링 + VLM 평가처럼 **반복적이고 시간이 걸리는 작업**이 병목
- AI 에이전트가 자율적으로 연구의 루틴 작업을 수행하고, 인간은 **핵심 판단(라벨링, 방향 결정)**에만 개입하면 효율적

### 1.2 핵심 가정
- Claude Code 세션이 장시간(수일~수주) 유지될 수 있음
- Cron 기반 자동 invoke로 일일 작업 사이클 구현 가능
- 파일 기반 상태 관리로 세션 간 연속성 확보
- 인간-AI 비동기 협업이 텔레그램 등 메시징으로 가능

## 2. 아키텍처

### 2.1 구성 요소

```
┌──────────────────────────────────────────────┐
│              연구 지시 문서 (Directive)          │
│  research_directive.md                        │
│  • [USER-ONLY] 영역: 인간만 변경 가능           │

├──────────────────────────────────────────────┤
│              상태 관리 (State)                  │
│  research_state.json                          │
│  • Phase 진행률                                │
│  • 시나리오별 완료 상태                          │
│  • 라벨링 큐 상태                               │
│  • 누적 산출물 수                               │
├──────────────────────────────────────────────┤
│              일일 로그 (Daily Log)              │
│  docs/daily_log.md                            │
│  • 날짜별 작업 내역                             │
│  • 이슈/블로커 기록                             │
│  • 다음 날 계획                                │
├──────────────────────────────────────────────┤
│              라벨링 파이프라인                    │
│  labeling_queue/pending/   → 인간 라벨링 →      │
│  labeling_queue/completed/ → benchmark/labels/  │
├──────────────────────────────────────────────┤
│              Cron 스케줄                        │
│  메인 세션 + 워치독 (이중화)                     │
│  라벨링 요청 + 일일 보고                        │
└──────────────────────────────────────────────┘
```

### 2.2 Cron 스케줄 (이중화 설계)

| 시간 | 역할 | 유형 |
|------|------|------|
| 06:03 | 메인 자율 연구 세션 | 메인 |
| 08:17 | 워치독 — 오전 세션 실패 시 복구 | 워치독 |
| 09:02 | 라벨링 요청 텔레그램 발송 | 커뮤니케이션 |
| 12:43 | 워치독 — 정오 점검/이어서 작업 | 워치독 |
| 15:51 | 워치독 — 라벨 수거 + 추가 작업 | 워치독 |
| 18:23 | 워치독 — 저녁 마무리/배치 준비 | 워치독 |
| 21:07 | 일일 진행 보고 텔레그램 | 커뮤니케이션 |

**이중화 원리:** 메인 세션이 실패하거나 중단되어도 2~3시간 내에 워치독이 감지하여 복구. 하루에 최대 5번의 작업 기회 → 1~2회 실패해도 일일 작업량 확보 가능.

**워치독 로직:**
1. daily_log에서 오늘 작업 기록 확인
2. 기록 없음/불완전 → 메인 세션 실패로 판단 → 작업 재개
3. 기록 완전 → 추가 작업 가능 여부만 판단

## 3. 제한 사항과 대응

### 3.1 Cron 세션 제한
- **문제**: CronCreate는 세션 기반, 7일 후 자동 만료
- **대응**: Day 7에 재등록 필요. daily_log에 리마인더 기록.
- **장기 개선**: `schedule` (Remote Triggers) 활용 검토 → 세션 독립적

### 3.2 세션 중단 리스크
- **문제**: 세션이 닫히면 모든 cron 중단
- **대응**: 모든 상태가 파일로 저장되므로, 새 세션에서 즉시 재개 가능
- **장기 개선**: 세션 헬스체크 메커니즘 (외부 모니터링)

### 3.3 컨텍스트 윈도우 압박
- **문제**: 장시간 세션에서 컨텍스트 누적 → 성능 저하
- **대응**: 매 cron invoke가 독립적 프롬프트로 실행 (자연스러운 컨텍스트 리셋)
- **대응**: 핵심 정보는 모두 파일에 저장 (컨텍스트 의존 최소화)

### 3.4 OpenFOAM 실행 실패
- **문제**: Docker 타임아웃, 솔버 발산 등
- **대응**: 실패 케이스를 daily_log에 기록, 다음 세션에서 재시도 또는 스킵
- **대응**: 타임아웃 넉넉히 설정 (foamToVTK 120s → 600s로 초기 수정)

## 6. 향후 개선 아이디어

1. **Remote Triggers로 전환**: 세션 독립적 스케줄링 → 7일 제한 해소
2. **자동 라벨링 보조**: VLM 예측을 pre-fill하고 인간은 검증만 (active learning)
3. **적응적 스케줄링**: 작업량에 따라 cron 빈도 동적 조정
4. **다중 프로젝트 확장**: 동일 프레임워크를 다른 연구 주제에 재사용
5. **품질 메트릭 자동화**: Figure QC를 Gemini/Codex로 자동 수행, 실패 시만 인간 개입
6. **진행률 대시보드**: 텔레그램 대신 웹 기반 대시보드로 실시간 모니터링
